# «Ұстаз» — мұғалімге арналған білім беру порталы

Қазақстан мектептеріне арналған веб-портал: қатысу, оқушы қозғалысы, БЖБ/ТЖБ енгізу және талдау, тоқсандық есеп (PDF/Excel/CSV), аналитика, ескертулер, аудит, рөлдер бойынша қолжетімділік және бірнеше мектепті қолдау. Интерфейс қазақ тілінде, орыс және ағылшын тілдерін қосуға дайын (i18next).

## Архитектура

```
Браузер ──HTTPS──► nginx (TLS, HSTS, CSP, rate limit)
                    ├── /api/*  ──► backend  (NestJS 11, REST, Swagger)  ──► PostgreSQL 16
                    │                                                    └─► Redis 7 (кэш, rate limit)
                    └── /*      ──► frontend (React 18 + Vite, статикалық nginx)
certbot ── Let's Encrypt сертификатын автоматты жаңартады
```

| Қабат | Технология |
|---|---|
| Frontend | React 18, TypeScript, Vite, TanStack Query/Table, Recharts, i18next, IBM Plex |
| Backend | NestJS 11, Prisma 6, class-validator, argon2id, JWT (httpOnly cookie), pdfmake, exceljs |
| Дерекқор | PostgreSQL 16 (Prisma миграциялары), Redis 7 |
| Инфрақұрылым | Docker Compose: `frontend`, `backend`, `postgres`, `redis`, `nginx`, `certbot` |

**Код құрылымы**

```
backend/
  prisma/schema.prisma        28 модель: мектеп, оқу жылы/тоқсан, сынып, пән, оқушы, қозғалыс,
                              сабақ, қатысу, бағалау (+критерийлер), деңгейлер, есеп, хабарлама, аудит, backup
  prisma/migrations/          SQL миграциялар
  prisma/seed.ts              рөлдер, анықтамалықтар, бірінші admin/мектеп; SEED_DEMO=true — демо мектеп
  src/common/                 guards (JWT, RBAC, CSRF), кэш, шифрлау, статистика, валидаторлар
  src/modules/<модуль>/       әр модуль: controller + service + DTO
frontend/
  src/components/             DataTable, Card, Modal, StatusButtons, графиктер, сүзгілер…
  src/pages/                  әр бет бөлек (lazy-load)
  src/i18n/                   аудармалар (kk.json; ru/en файлдарын қосуға болады)
deploy/
  nginx/templates/            edge nginx конфигурациясы (HTTPS)
  scripts/                    init-letsencrypt.sh, backup.sh, restore.sh, deploy.sh
```

Әр мектептің деректері `school_id` арқылы бөлінген (multi-tenant). Жаңа мектеп «Басқару → Мектептер» бетінде қосылады. AI-ға дайын: талдау мәтіндері `InsightsProvider` интерфейсі арқылы жасалады (`backend/src/modules/insights`). Қазір ережеге негізделген, кейін LLM-ге ауыстыруға болады.

|---|---|
| Басты бет | KPI (оқушы, ұл/қыз, сынып, бүгінгі қатысу, қозғалыс, үлгерім, БЖБ/ТЖБ), 8 график, кезең: бүгін/апта/ай/тоқсан/жыл, «келесі әрекет» |
| Оқушылар | Іздеу, сүзгі, сұрыптау, пагинация, баған көрінісі, экспорт; профиль, ЖСН (рұқсатпен, аудиттеледі), тарих |
| Қатысу | Сынып/пән/күн/сабақ; ✓ Н С А К Б; «Барлығы қатысты»; пернетақта (1–6, ↑↓); күнтізбе; төмен қатысу ескертуі |
| Қозғалыс | 6 түр, бұйрық №/күні, себеп, түсініктеме; жыныс/ұлт статистикасы (ұлт — тек әкімшілікке) |
| БЖБ / ТЖБ | Критерийлер бойынша енгізу, автоматты %/деңгей/сапа/үлгерім, мобильде − / + |
| ТЖБ талдауы | Оқушы · балл · % · деңгей · нәтиже; әлсіз/күшті критерийлер; қорытынды |
| Тоқсандық есеп | 14 бөлім, I→IV салыстыру; PDF (ресми түр), Excel (4 парақ), CSV; тапсыру |
| Аналитика | Тоқсандар, сыныптар, пәндер, оқушы, ұлт (рұқсатпен), тәуекел тобы |
| Хабарламалар | Ережелер: төмен қатысу, ТЖБ төмен деңгей, кеткен оқушылар, тапсырылмаған есеп |
| Аудит | Кім, қашан, не, ескі → жаңа мән, IP |
| Баптаулар | Деңгей диапазоны (0–100 толық, қабаттасусыз), қатысу шегі, тақырып, backup, рөлдер матрицасы |
| Басқару | Пайдаланушылар, сыныптар (жетекші, пән мұғалімдері), пәндер, оқу жылдары, мектептер |

API құжаттамасы (Swagger): `SWAGGER_ENABLED=true` болса `https://<домен>/api/docs`.

## Рөлдер және қауіпсіздік

| Рөл | Қолжетімділік |
|---|---|
| Мұғалім (`TEACHER`) | Тек өзі сабақ беретін және жетекшісі болып табылатын сыныптар. Қатысу, бағалау, қозғалыс, есеп |
| Мектеп әкімшілігі (`SCHOOL_ADMIN`) | Бүкіл мектеп, ЖСН, ұлт статистикасы, деңгейлер, сыныптар, аудит |
| Жүйе әкімшісі (`ADMIN`) | + пайдаланушылар, мектептер, резервтік көшірме, барлық мектепке ауысу |

Рұқсаттар `roles.permissions` бағанында сақталады және **API деңгейінде** тексеріледі (`PermissionsGuard` + `ScopeService`). Фронтендтегі жасыру тек ыңғайлылық үшін.

- Құпиясөз: argon2id. 5 қате кіруден кейін 15 минутқа бұғаттау, уақыт бойынша шабуылға қорғаныс.
- Сессия: қысқа мерзімді access JWT (15 мин) және ротацияланатын refresh token. Екеуі де `httpOnly`, `Secure`, `SameSite=Strict` cookie. Құпиясөз өзгерсе, ескі токендер жарамсыз болады.
- CSRF: double-submit token (`X-CSRF-Token`).
- Валидация: барлық DTO `class-validator` арқылы тексеріледі (whitelist, белгісіз өріске тыйым).
- SQL injection: тек Prisma параметрлі сұраулары. XSS: React escaping және қатаң CSP. CSV экспортында формула инъекциясынан қорғаныс бар.
- Rate limit: nginx (кіруге 10/мин, API 20/с) және backend (Redis арқылы).
- ЖСН AES-256-GCM-мен шифрланады. Іздеу HMAC хэші бойынша жүреді. Толық ЖСН тек рұқсатпен көрсетіледі және әр ашылуы аудитке жазылады.
- HTTPS (TLS 1.2/1.3), HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy.
- Аудит: барлық өзгеріс транзакция ішінде жазылады. Аудит жазылмаса, өзгеріс те сақталмайды.

## Жергілікті іске қосу

Талаптар: Node.js 22, PostgreSQL 16, Redis 7.

```bash
# Backend
cd backend
cp ../.env.example .env        # DATABASE_URL, REDIS_URL, кілттерді жергілікті мәндерге өзгертіңіз; COOKIE_SECURE=false
npm ci
npx prisma migrate deploy
SEED_DEMO=true npm run seed    # демо: №1 мектеп, 9 сынып, 200+ оқушы
npm run start:dev              # http://localhost:3000, Swagger: /api/docs

# Frontend
cd ../frontend
npm ci
npm run dev                    # http://localhost:5173 (/api → localhost:3000)
```

Демо кіру деректері (құпиясөз `Ustaz2026!`):

| Логин | Рөл |
|---|---|
| `admin` | Жүйе әкімшісі |
| `bekova` | Мектеп әкімшілігі |
| `akhmetova` | Мұғалім, 9А жетекшісі |

Тесттер: `cd backend && npm test`.

## VPS-ке орнату

Ubuntu 22.04/24.04, 2 vCPU, 4 ГБ RAM жеткілікті.

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Код
git clone <репозиторий> /opt/ustaz && cd /opt/ustaz

# 3. Баптаулар
cp .env.example .env
nano .env        # DOMAIN, құпиясөздер, кілттер (openssl rand -hex 32), ADMIN_PASSWORD

# 4. HTTPS сертификаты (DNS A-жазбасы серверге бағытталған болуы керек)
./deploy/scripts/init-letsencrypt.sh admin@mektep.kz

# 5. Іске қосу
docker compose up -d --build
docker compose ps
```

Backend әр іске қосылғанда миграцияларды (`prisma migrate deploy`) және идемпотентті seed-ті орындайды. Бос дерекқорда бірінші мектеп (`SCHOOL_NAME`), ағымдағы оқу жылы және admin пайдаланушы жасалады. Одан кейін `https://<домен>` сайтына `ADMIN_LOGIN` / `ADMIN_PASSWORD` арқылы кіріп, «Басқару» бетінде сыныптар, пәндер және мұғалімдерді қосыңыз.

Firewall: тек 22, 80, 443 порттары ашық болуы керек. PostgreSQL мен Redis сыртқа шығарылмайды.

## Резервтік көшірме

- **Автоматты:** backend күн сайын 02:00-де (Алматы) `pg_dump` көшірмесін `backups` томына жасайды. Ескілері `BACKUP_RETENTION_DAYS` бойынша өшіріледі. «Баптаулар → Резервтік көшірмелер» бетінде көшірме жасауға, жүктеп алуға, өшіруге және кестені өзгертуге болады.
- **Сервердегі көшірме:** `./deploy/scripts/backup.sh` файлды `./backups/` ішіне жазады. Сыртқы дискке немесе бұлтқа синхрондау ұсынылады. Cron мысалы скрипттің ішінде.
- **Қалпына келтіру:**
  ```bash
  ./deploy/scripts/restore.sh backups/ustaz_20261101_033000.dump
  ./deploy/scripts/restore.sh --volume ustaz_auto_20261101_020000.dump   # backend жасаған көшірме
  ```
  Скрипт алдымен ағымдағы күйдің көшірмесін жасайды, растау сұрайды, backend-ті тоқтатады, қалпына келтіреді және кэшті тазалайды.

> `PII_ENCRYPTION_KEY` кілтін дерекқор көшірмесінен бөлек, қауіпсіз жерде сақтаңыз: онсыз шифрланған ЖСН-дерді ашу мүмкін емес.

## iMARLEN ID арқылы кіру

Портал iMARLEN ID-ға (OpenID Connect, authorization code + PKCE) қосылады. Мұғалім «iMARLEN ID арқылы кіру» батырмасын басады, id.imarlen.kz-те кіреді және порталға оралады.

1. **Клиентті тіркеу** (id.imarlen.kz серверінде):
   ```bash
   docker compose exec id node --disable-warning=ExperimentalWarning src/cli.mjs client ustaz "Ұстаз" \
     https://<домен>/api/auth/callback https://<домен>/ https://<домен>/
   ```
   Шыққан `client_secret`-ті Ұстаз серверіндегі `.env` файлына `IID_CLIENT_SECRET` ретінде жазыңыз (чатқа, git-ке салмаңыз). `IID_CLIENT_ID=ustaz`.
2. `docker compose up -d backend` — кіру бетінде батырма пайда болады.
3. **Мектептерді байланыстыру:** «Басқару → Мектептер → Өңдеу» бетінде iMARLEN ID-дағы мектеп кодын (мыс. `s51`) көрсетіңіз.

Ережелер:

| iMARLEN ID рөлі | Порталдағы рөл |
|---|---|
| `teacher` | Мұғалім |
| `school_admin` | Мектеп әкімшілігі |
| `platform_owner` | Admin |
| `student`, `parent` | кіргізілмейді |

- Пайдаланушы `sub` бойынша табылады. Табылмаса, сол мектептегі логині `preferred_username`-ге тең бұрынғы аккаунт бір рет байланыстырылады; болмаса жаңа аккаунт автоматты жасалады. Әр кіруде аты, рөлі және мектебі iMARLEN ID бойынша жаңартылады, рөл өзгерісі аудитке жазылады.
- Порталда бұғатталған немесе жойылған аккаунт iMARLEN ID арқылы да кіре алмайды.
- `IID_PASSWORD_LOGIN=false` болса, тек Admin құпиясөзбен кіре алады (апаттық кіру үшін).
- SSO арқылы кірген пайдаланушы шыққанда iMARLEN ID сессиясы да жабылады.

## Env айнымалылары

Толық тізім мен түсініктемелер `.env.example` файлында. Негізгілері:

| Айнымалы | Мақсаты |
|---|---|
| `DOMAIN`, `CORS_ORIGIN` | Сайт домені |
| `POSTGRES_*`, `REDIS_PASSWORD` | Дерекқор және кэш |
| `JWT_ACCESS_SECRET` | Токен қолтаңбасы (32+ таңба) |
| `PII_ENCRYPTION_KEY`, `PII_HASH_KEY` | ЖСН шифрлау және іздеу хэші (64 hex) |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Бірінші әкімші |
| `SCHOOL_NAME`, `SCHOOL_SHORT_NAME` | Бірінші мектеп |
| `SEED_DEMO` | Демо деректер |
| `SWAGGER_ENABLED` | API құжаттамасы |
| `IID_ISSUER`, `IID_CLIENT_ID`, `IID_CLIENT_SECRET` | iMARLEN ID арқылы кіру |
| `IID_PASSWORD_LOGIN` | Құпиясөзбен кіруді қалдыру (әдепкі `true`) |

Production режимінде әлсіз немесе әдепкі кілттермен backend іске қосылмайды.
